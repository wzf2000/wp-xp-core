# 使用指南

简体中文 · [English](GUIDE.en.md) · [返回首页](../README.md)

本指南面向站点管理员，描述 **2.0.0-rc.2 预发布版**。已发布版本请阅读对应 Release 标签内的指南。1.4.0 起，新站安装并启用即可使用默认经验规则，无需服务器 JSON 配置。下载安装步骤见[首页](../README.md#开始使用)。

## 创建经验页面

“经验页面” 是普通 WordPress 页面，用来显示每位登录用户自己的经验，不是必须已有的 “账户页”。按以下步骤创建：

1. 后台进入 **页面 → 新建页面**，标题填写 **我的经验**（也可自定义）。
2. 点击编辑器的 **＋** 添加区块，搜索并选择 **短代码**。
3. 在区块输入框中粘贴：

   ```text
   [reader_experience]
   ```

4. 点击右上角 **发布**，确认发布。页面使用公开、无密码保护的设置即可；匿名访客只会看到登录入口，不会看到别人的经验记录。
5. 进入 **设置 → WP XP Core → 添加经验面板**，选择刚发布的页面，点击 **保存面板页面**。该操作只指定链接目标，不创建或发布页面。
6. 打开该页面并登录，可查看经验、等级、距下一级的经验，点击签到并展开最近记录。顶栏 “经验签到” 与登录返回链接也会指向此页。

可以从 WordPress 的菜单／导航编辑器将该页面加入导航，方便用户访问。如果不指定页面，链接使用当前页面或首页。高级外部接入的站点继续使用配置中的面板页面和短代码，见[高级接入](CONFIGURATION.md#可选外部配置)。

## 设置经验规则

进入 **设置 → WP XP Core**，也可点击插件列表中的 **设置**。保存需要管理员的 `manage_options` 权限。

### 日常活动

分别开启或关闭签到、有效阅读、发表文章和评论，设置经验值，以及阅读与评论每日奖励次数。各活动奖励允许 **0–1000000** 的整数；每日次数允许 **0–1000**。

- **奖励设为 0：** 仍保留符合条件的事件记录，避免之后调整奖励时重复领取。
- **每日次数设为 0：** 停止对应类别的奖励。
- **每日签到：** 每个账号每天一次。
- **有效阅读：** 登录用户在可访问页面满足设定的停留时间（默认 15 秒）；同一账号、同一页面、同一天的阅读奖励最多一次，另受全站规则中的每日次数限制。
- **发表文章：** 公开的 `post` 文章每篇只奖励一次；再次编辑或重新发布不会重复领取。
- **评论：** 需要登录账号，评论已获批准，位于公开文章或页面，且评论者不是文章作者，也不是回复自己的评论。评论失去资格时完整扣回原实际奖励，恢复资格后按原实际金额恢复。若余额不足，账本和经验保持原样，补偿进入失败列表供管理员处理；不会部分扣减或产生负余额。

阅读停留时间可设为 **5–3600 秒**。每日统计默认使用 **Asia/Shanghai（UTC+8）**；只有账本没有任何事件时才可修改时区。

在 “适用内容与每日统计时区” 中填写文章／页面 ID 或分类 ID：两项都留空表示全部，填写后命中任意一项即可。范围作用于阅读、文章、评论与作者里程碑；页面不按文章分类匹配，也不会因此开放受限内容。关闭活动停止新的奖励，已发评论的撤销／恢复仍按原金额处理。

### 可选的活动经验上限

每日与每周活动经验上限默认为 **0（不限）**，可设 0–1000000000。使用经验时区，每周从周一开始；同时开启时取更小的剩余额度。签到、阅读、发表文章、首次评论奖励、作者里程碑、签到阶段及自动／审核任务奖励共同累计本期首次奖励实际发放的正向经验。

额度不足时只发剩余部分，触顶仍保留 0 经验事件及领取标识，之后不补差额。扣回奖励不恢复额度；评论原金额恢复属于补偿，不再次占用或受上限限制。人工调分／人工授予及其撤销、历史迁移不计入。开启上限时，本期已发的首次奖励也计额度，但保存设置不会回收旧奖励。账本依据保留当时请求额、实际额、上限与截断原因。

### 作者里程碑

浏览与点赞默认各三档，每组可增删至 **0–20 档**。每档可以修改触发次数和经验值，同组次数必须为 **1–1000000000** 的严格递增整数。

浏览里程碑按经验账本记录的有效浏览计数：登录用户阅读公开文章、不是文章作者，同一用户同一文章每天一次。它不等同于分析工具统计的所有页面浏览。点赞里程碑同样使用已记入经验账本的点赞事件，而非直接使用外部插件的总数。

每篇文章每档只领取一次。移除后保存会永久停用该档标识；重新添加的是新档位，不能恢复为旧档。修改门槛不会重置已领取档位，保存也不发奖。例如，将第一档从 100 次改成 50 次，一篇已有 80 次账本浏览且未领取该档奖励的文章，会在下一次有效浏览时达标。

点赞需 **PageNest Companion** 的点赞接口可用，且点赞功能已开启；否则该组禁用并显示原因。保存其他设置会保留原有点赞规则。

### 等级成长

逐行填写各等级最低经验，使用添加／移除控件调整等级数量。支持 **1–100 级**，第一级固定为 **0**，其余门槛严格递增，每项不超过 **1000000000**。添加和移除行需要 JavaScript；没有 JavaScript 时仍可修改已有行。

例如，门槛为 `0、10、30`，经验为 25 的用户显示 Level 2，距离 Level 3 还需 5 经验。将第三级门槛改为 20 后，该用户立即显示 Level 3，余额仍为 25。

### 保存与生效

点击 **保存经验规则**。无效输入会保留之前的设置；如果另一位管理员已保存更新，重新打开页面再修改，避免旧表单覆盖新规则。

奖励变更只用于之后首次记账的事件，历史经验不会重算或补发；评论撤销／恢复使用首次奖励金额。等级变化立即用于展示。未保存过规则的站点使用默认值；已保存配置无效时会提示管理员并使用默认值。打开页面不会自动创建或保存设置。

## 查询与调整经验

1. 从插件页导航进入 **事件账本**，按用户编号、事件来源和日期查询；可按用户名或显示名称查找用户并核对余额、等级和记录。
2. 需要人工调整时，填写用户编号、增减经验及原因后提交。单次为 -1000000 至 1000000 的非零整数，扣减不能超过当前余额；操作会追加事件，保留管理员及原因。
3. 调错时，在 “撤销人工调整” 填写原事件编号和撤销原因。只能撤销人工调整，且每笔只能撤销一次；它会追加反向记录，不能删除原记录或将余额扣为负数。

查询导出只包含当前筛选和分页范围，并非自动导出整个账本。导出文件包含用户编号、活动来源、经验变化和日期，不包含管理原因；仍应按站点的私人数据保管。

进入 **运行诊断** 可分页比较账本合计与余额。诊断只读，不自动修正差异。页面中的重试仅针对服务端已捕获的首次文章／评论奖励失败，以及评论状态补偿失败。管理员填写原因后，重新检查原事件归属、当前资格（含永久删除）、原实际金额与净额，再完整补偿；余额不足时继续保留。若评论已恢复而原净额仍在，则仅将事项标为解决，不再加经验。失败列表最多保留 200 项，不是永久日志，不扫描旧文章或评论。配置审计可用于核对规则变更。

## 配置成长中心

打开 **成长中心**，为各级设置名称、图标字符、颜色和简短说明。门槛仍在 “经验规则” 修改，等级资料只影响展示。原有经验短代码继续使用，无需另建页面。个人页面按当前登录用户显示等级进度、最近 35 天签到日历、连续／累计签到和可筛选分页的私人记录；匿名访客不能查看个人记录。

额外 “签到成长奖励” 默认关闭。如需启用，选择连续或累计签到，添加天数与奖励后保存。启用或修改阶段奖励规则后从下一次新签到开始累计，不补发旧签到；每档在本版规则下只领取一次。连续签到中断后重新累计，但不扣回已经获得的经验。每日签到与当次触发的阶段奖励同时记账，避免只发其中一部分。查看页面或日历不会发奖。

## 创建任务与成就

在 **任务与成就** 新建任务，填写名称、说明和图标字符，选择启用状态与周期：一次性、每日、每周或每月。周期使用经验时区，每周从周一开始，每月从一日开始。最多保存 **50 项任务（包含停用项）**。

- **自动任务：** 添加 1–8 个步骤，每步选择签到、阅读、评论或发表文章及 1–1000 的目标；可按活动次数、不同内容或不同自然日计数。不同内容按文章／页面去重，评论归属同一文章只算一项；签到支持活动次数或自然日。文章／页面 ID 与分类 ID 任意命中即可，两者为空表示不限；页面不匹配文章分类。范围不会开放私人、草稿或密码保护内容。所有步骤都满足才完成。统计符合规则并记入账本的新活动，不按页面访问次数计数。
- **审核任务：** 不设置自动步骤。用户在自己的经验页面提交完成说明，管理员在待审核列表中通过或退回；退回必须说明原因。每位用户在同一任务、版本和周期最多提交 5 次，同时只能有一份待审核说明。

开放日期可留空，填写时包含起止当天；未开放或已结束时不能完成、领取、提交或通过审核。在可选前置任务中可选择最多八项，全部满足后才能领取或提交。每项可要求前置任务的当前版本与当前周期，或终身任何版本已经获得的荣誉；不允许引用不存在的任务或形成循环。前置条件不改变本任务的活动起点，符合本版日期范围的新活动仍可累计。

任务默认只授予荣誉，可在 “成就展示与可选奖励” 设置 0–1000000 的完成经验。0 表示不加经验；自动完成与审核通过都按该版本奖励一次。修改奖励会建立新版本，不向旧成就补发。修改名称、说明、图标字符、徽章图片、分类或系列会保留当前版本和进度。修改完成方式、步骤、周期、日期、前置条件或启用状态会创建新版本；新版只计之后的新事件，不接续旧版进度或扫描历史补齐。已获成就保留授予时的文字与图标。

徽章可以从媒体库选择公开图片，也可使用字符图标。图片删除、变为私人内容的附件或不再可用时回退字符。个人面板保留成就授予时的名称、图标、图片引用、分类、系列、条件和实际奖励，并显示获得时间；以后编辑展示资料不改写旧快照。

在 “人工授予与撤销” 中填写用户编号、当前任务和原因，可根据独立核实的依据授予成就；仍检查任务版本、周期、开放日期、前置与目标用户权限。人工授予经验单独记录，不进入活动榜。一个人对同一任务、版本与周期只能获得一次，审核或其他途径不能重复领奖。

撤销时从事件账本查找原 “完成任务” 或 “人工授予成就” 事件编号，填写原因。撤销追加反向记录并扣回原经验；余额不足时成就和经验都保留。零经验荣誉也可撤销。已撤销成就不再显示为已获得，不满足前置条件，且本版本本周期不能重新授予。撤销前置荣誉会阻止后续新领取，不会自动级联撤销已经获得的后续成就。历史事件始终保留。

个人经验记录的来源筛选包含任务完成奖励、任务奖励撤销、人工授予成就及撤销人工成就。自动／审核完成与对应撤销参与本期活动净经验；人工授予及其撤销只在管理来源分析单独显示。

## 查看私人通知与下一步目标

个人成长面板的 “站内通知” 显示之后新发生的成就授予／撤销、审核通过／退回和真正升高的等级。普通阅读经验不会逐条产生通知；修改等级设置本身也不发升级通知。通知只在本人登录后展示，不发邮件，不建立定时任务。点击 “刷新通知” 可重试读取，逐条或按当前已读取范围全部标为已读；“通知偏好” 可分别关闭成就、审核或等级消息，重新开启不会删除旧消息或已读状态。

通知从已保存的经验事件恢复，通知暂时不可读不会撤回已成功的奖励。重复打开面板不会再授予成就、加经验或生成重复消息；升级通知使用事件发生时的前后等级，之后修改门槛不会改写旧消息。更新前没有通知快照的旧事件不会补生成历史通知。

任务列表提供下一步目标、剩余数量、不同内容／不同自然日的计数方式、当前可访问的指定内容／分类链接，以及前置任务名称、完成状态与要求的版本／周期。私人、密码保护或尚未公开的内容不会显示名称或链接。指定范围仍受有效活动资格约束，不会因点链接立即完成任务。

## 放置周榜与月榜

新建普通页面，添加短代码区块，按需要填写以下任一短代码并手动发布：

```text
[xp_leaderboard period="week" limit="10"]
[xp_leaderboard period="month" limit="10"]
```

`period` 支持 `week`（默认）或 `month`；`limit` 是每页人数，默认 10，范围为 1–50。插件不自动创建或发布榜单页面。榜单可供匿名访客查看，只展示名次、显示名称、公开作者链接和本期净经验。

本周从当前经验时区的周一统计至今日，本月从月初统计至今日，页面会标明日期和时区。计入签到、阅读、发表文章、评论、作者里程碑及签到阶段奖励，扣回与恢复按期间内的账本事件计算净额；不计历史迁移、余额校准、人工调分或零经验荣誉。只有本期净经验大于 0 的现有用户上榜；已删除用户及多站点中已退出当前子站的用户不展示。周月切换只是改变统计范围，不重置余额。

同分并列，例如 1、1、3。结果实时计算，分页请求之间发生新活动时，名次和页面中的用户可能变化。登录后的成长面板通过 JavaScript 提供本周／本月的 “本人位置”；没有符合条件的正净经验时无排名。该入口只查询当前账号，不提供查询其他用户私人记录的入口。

个人面板可取消 “参与公开活动榜”，只影响公开排名，经验、私人通知与任务照常保留。管理员可在激励效果页按用户编号排除测试账号等对象。退出或被排除时，“本人位置” 明确显示未参与榜单；管理员恢复资格也会保留用户自己的退出选择。

## 查看激励效果

进入 **设置 → 激励效果**，也可从插件导航打开，需要 `manage_options` 权限。

**经验来源** 可选择本周、本月或自选日期。自选范围包含起止日期，最长 366 天，结束日期不得晚于经验时区的今日。各来源显示发放经验、扣回经验、净经验、事件数和去重参与人数；奖励为 0 的有效活动也计入事件与人数。总参与人数跨来源去重，不能将各行人数相加。

这里把人工调整和撤销人工调整单独列为来源，并计入总数，因此与公开活动榜的范围不同。任务完成和撤销计入来源统计（零经验荣誉也计事件与人数）；人工授予及其撤销单列，历史迁移、校准与管理操作回执不计入。已删除用户的既有事件仍保留在脱敏汇总中，不显示个人明细。

**当前任务完成率** 只统计当前启用任务的当前版本和当前周期，不随上方来源日期切换。分母是有匹配活动记录（自动任务）或审核提交记录（审核任务）的用户与完成者的去重并集，分子是取得该版、该周期成就的去重用户。它不是页面曝光转化率，也不是全站注册用户的完成比例；没有参与者时显示 “尚无参与”，不按 0% 处理。修改任务产生新版本后，旧版参与和完成记录不混入新版。

榜单、个人位置和效果统计均为只读：查看不会发经验、重置任务或触发补奖，也不建立统计表或定时任务。

激励效果还提供**前一等长时段对比**，把所选范围与紧邻的同样天数作描述性比较，不据此推断任务的因果效果。**活动线索**仅列出同日首次活动至少 20 次或发生上限截断的账号供人工核对，不自动处罚。

**任务版本完成记录**显示时段内授予、撤销及这些授予目前仍有效的数量。旧版本缺少完整定义时不计算参与分母或留存。新授予保存定义创建时间作为耗时起点；平均秒数包含等待与未参与的时间，不是用户实际花费时间，没有起点证据的旧记录留空。每次最多展示最近 100 个版本，可缩短日期范围。

## 常见问题

### 为什么显示 “经验系统维护中”？

新安装站点先确认插件已成功启用。若启用报错，请按错误提示检查数据库权限和 InnoDB 支持；插件不会改造其他 WordPress 表。停用后重新启用会保留账本与设置，不会重置经验。

高级外部接入的站点请按[接入核对](CONFIGURATION.md#接入核对)检查原有配置与运行开关。配置有误时不会自动切换到新的空账本。

### 为什么阅读或评论没有增加经验？

先检查登录状态、奖励是否为 0、是否达到每日次数、是否已经领取，以及活动是否满足上面的资格。阅读还需满足设定的停留时间（默认 15 秒）。重复请求不会重复发奖，访问次数也不直接等同于奖励次数。

### 为什么点赞设置不可编辑？

PageNest Companion 未提供可用点赞接口，或其点赞功能未开启。启用并完成该插件自身配置后再打开设置页；WP XP Core 不自带点赞服务。

### 修改经验奖励后，旧记录为什么不变？

旧事件保留当时的金额。新规则只影响之后首次记账的事件；将奖励从 0 调高也不会重发已经记录的事件。

### 可以手动修改某个用户的经验吗？

可以，进入 “事件账本” 查找用户，填写增减数值及原因。请按上面的管理流程操作，不直接修改余额元数据。

### 怎样更新插件？

从 [Release](https://github.com/wzf2000/wp-xp-core/releases/latest) 下载安装 ZIP，备份后通过 WordPress 上传并替换当前版本。插件没有自动更新器。从旧 Reader Experience 迁移时，还需按[兼容与升级](CONFIGURATION.md#兼容与升级)切换目录及提前加载入口。

### 怎样反馈问题？

在 [Issues](https://github.com/wzf2000/wp-xp-core/issues/new/choose) 说明插件、WordPress 与 PHP 版本，附复现步骤和预期／实际结果。截图与日志请先去掉账号明细、验证令牌和服务器私有配置；安全问题使用[私密报告渠道](../SECURITY.md)。
